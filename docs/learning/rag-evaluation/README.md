## 0. 为什么单独建这个专题

`docs/learning/` 下已有多篇评估相关文档，质量都很高，但**全部是 Explanation（解释性）体裁** —— 预设读者已经知道这东西是干什么的，来搞懂原理。

实际读下来会卡在几个**具体的地方**：

| 卡点 | 深文/既有章节里的写法 | 缺的前置 |
|---|---|---|
| 02 章 § 1 相关性标注 | 「哪些 chunk 是相关的」 | **chunk 是什么、chunk_id 由什么决定、为什么评估以片段为单位** |
| 02b 章 两个 recall | 「`custom__recall` 0.30 与 `ragas__context_recall` 0.83 可以同时是对的」 | **一次评估运行到底做了几件事，每个指标读的是哪几个字段** |
| ragas-basics § 4.1 | 「把 answer 拆成 statements，拿 contexts 逐条做 NLI」 | **judge 在代码里是什么形态；NLI 是什么** |
| golden-test-set § 2 | 「一条 case 里有两种答案」 | **`ground_truth` 与 `expected_chunk_ids` 分别喂给谁** |
| CLAUDE.md 降级治理 | 「judge 输出无法解析时该 case 记 NaN，不计入分母」 | **NaN 是什么、平均值的分母为什么会变** |
| 02 章 § 7 Q5 | 「42 条上 0.04 的差异很可能是噪声」 | **小样本的分辨率：一条 case 值多少分** |
| CLAUDE.md 异源判据 | 「`glm:minimax/minimax-m2.7`，provider 名义是 glm 但路由到 minimax」 | **模型标识串、网关链路** |

**这些不是可选背景，是理解结论的唯一前提。** [00 章](00-prerequisites.md) 补的就是这七级台阶。

> **本专题不重写深文的内容。** 每章只搭最低限度的台阶，讲完就交接过去（§ 4）。

## 先用人话说：这到底是在学什么

> **第一次接触评估的人先读这一段（5 分钟），别急着看下面的阶梯图。** 那张图里的词（锚定偏差、幸存者偏差、四道闸门）现在看只会让你更慌 —— 它是给读完的人回顾用的。

### 一句话：这是在学「怎么给 RAG 改卷子」

把 RAG 系统当成一个学生。它答题分两步：

1. **翻书** —— 从资料库里找出几段可能有用的材料
2. **答题** —— 照着找到的材料写答案

你要给它打分。麻烦在于：**你没法像批数学题那样对答案。** 同一个意思有一百种说法，字面完全不同但都对。整个 RAG 评估领域，就是在解决这一件事。

### 八章其实在回答八个人话问题

| 章 | 用人话说，这章在问什么 |
|---|---|
| 00 | 跑一次「考试」，机器到底做了哪几件事？**不搞清这个，后面全是黑箱** |
| 01 | 学生考砸了，是**没翻到该看的那页**，还是**看到了但瞎写**？这两种病吃的药完全不同 |
| 02 | 「有没有翻到该看的那页」怎么变成一个数字？**这层最扎实，纯算术，能拿纸笔算** |
| 03 | 「有没有瞎写」怎么变成数字？—— 只能再请一个 AI 来读、来判 |
| 04 | 等一下，**那份参考答案是谁写的**？（答案：也是 AI 写的）**这一章是地基** |
| 05 | ★ 既然参考答案是 AI 编的，**这些分数凭什么信**？ |
| 06 | 这次 62 分、上次 60 分 —— 是真进步，还是**换了张卷子**？ |
| 07 | 本项目这套卷子，现在哪里靠得住、哪里不靠得住 |

**05 是转折点。** 前四章你会觉得「评估就是把质量变成数字」；读完 05 你会明白：**这把尺子自己是有偏心的，它有时会给做对了的改动打低分。** 本项目最重要的一条结论就长在这一层 —— 重排模块明明在做正确的事，指标却在跌。

### 四件最容易让学习失败的事

1. **02 章光读不算。** 五个指标的差别，自己拿纸笔算一遍就懂了，光看表格记不住。
2. **急着跳到 05。** 05 的全部说服力来自「参考答案是怎么造出来的」—— 那是 04 章的内容。跳过 04 读 05，会觉得像在听阴谋论。
3. **跳过每章末尾的自测题。** 那不是装饰。答不上就是没学会，往下走只会越来越糊。
4. **把 2026-04 的旧文档当现行准则**（`ragas-tuning-playbook.md` / `rag-acceptance-plan.md`）。它们写在这套认识形成之前，**当史料读**（详见 § 4.5）。

### 别一天读完

六小时的量，分三四次，中间**必须隔夜**：

| 第几次 | 读什么 | 时长 |
|---|---|---|
| 1 | 00 + 01 + 02（打地基，要连着读） | 1.5 h |
| 2 | 03 + 深文一节（搞懂「请 AI 当裁判」） | 1 h |
| 3 | 04 + 深文全篇（搞懂参考答案的来路） | 1.5 h |
| — | **睡一觉** —— 下一次是分水岭，脑子要清醒 | |
| 4 | 05 读两遍 + 06 + 自己开一份真实报告实操 | 1.5 h |
| 5 | 07 收尾 | 20 min |

具体到「第几步读哪个文件」看 § 3.1。

> 这张图是**给读完的人回顾用的**。第一次读只需要知道「越往上越依赖下面」，看不懂里面的词是正常的。

├───────────────────────────────────────────────────────────┤

│               「这个改动到底算不算改进」                    │
├───────────────────────────────────────────────────────────┤
│ 05  元评估    锚定偏差 / judge 偏差 / 同源污染 / 幸存者    │

├───────────────────────────────────────────────────────────┤
│ 00  前置层    chunk / 评估流水线 / 金标字段 / judge / NaN  │

└───────────────────────────────────────────────────────────┘

**★ 05 是分水岭。** 在它之前，评估看起来是「把质量变成数字」的工程问题；理解元评估之后才会明白，**指标不是中立的观察者，而是有立场的参与者** —— 本项目最重要的一条结论（「没有可用于评判重排的离线指标」）就诞生在这一层。

**为什么从 02 而不是 03 入门**：检索指标是信息检索 50 年的积累，公式确定、答案唯一、可以手算验证。生成指标依赖 LLM 当裁判，一上来就学会把「指标本身的定义」和「裁判可能出错」两件事糊在一起。**先在确定的地面上站稳，再上不确定的楼层。**

## 3. 走法

⚠️ **如果你的目标是「系统掌握」而不是「快速了解」，就走这条 —— 不要只走 § 2 那 8 章。**

§ 2 是主干，但主干**刻意不重复深文的论证**（交接纪律）。只走主干会得到一套正确但单薄的框架：你会知道「金标有两代」，却没读过两代偏向的完整论证。**深文不是可选加餐，它们是这条路线的组成部分**，只是插入时机有讲究 —— 提前读会因为缺前置而读不动，推后读会让主干的结论悬空。

## 4. 评估文档全景地图

> **只有 § 2 那 8 章有「阅读顺序」。其余全部是「按需查」，不要顺读，也不要试图读完。**

散落是**故意的**，不是没整理：规格与验收文档必须留在它所属的那次变更旁边（这是 SDD 的追溯性要求），搬进 `docs/` 就断了「结论 ↔ 产生它的那次变更」的链条。所以解法是这张地图，不是搬文件。
