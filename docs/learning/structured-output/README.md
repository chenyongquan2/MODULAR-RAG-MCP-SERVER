# 结构化输出学习专题

> **建立日期**：2026-08-16
> **面向**：会 Python、调过 LLM API，但没深究过「怎么让模型稳定返回可被代码消费的数据」的人。
> **定位**：本专题是 **Tutorial（教程）** —— 有固定顺序、逐级递进、每章都短。查定义、查取舍论证请走 § 4 的参考层。

---

## 0. 为什么单独建这个专题

`docs/learning/` 下已有一篇 [structured-output-explained.md](../structured-output-explained.md)（1200 行），内容完整、带本项目实测数据。但它是 **Explanation（解释性）体裁** —— 预设读者已经知道 token、logits、采样、`finish_reason`、JSON Schema、pydantic 是什么。

实际读下来会卡在几个具体的地方：

| 卡点 | 深文里的写法 | 缺的前置 |
|---|---|---|
| §4 约束解码 | 「模型在整个词表上算概率分布，采样前把违规 token 概率置零」 | **token / logits / 采样三者的分工** |
| §8.2 推理 token | 「out=854, reason=849, 可见内容 5」 | **推理型模型是什么，为什么 content 会空** |
| §3.3 假函数 | `ScreeningVerdict(**args)` | **`**` 解包；类名与 tool name 是两个东西** |
| §5 形式文法 | 「能回答『下一个 token 合法集』的文法都能约束」 | **正则 / CFG / 状态机** |
| §8.5 网关 | 「参数未必被真实透传」 | **兼容端点、上游 provider 的链路结构** |

**这些不是可选背景，是理解结论的唯一前提。** 本专题补的就是这几级台阶。

> **本专题不重写深文的内容。** 每章只搭最低限度的台阶，讲完就交接过去。

## 1. 全景图：五层能力阶梯

自下而上依赖 —— 下层没懂，上层的结论一定会误读。

```
┌──────────────────────────────────────────────────────────┐
│ 05  落地层    生产纪律 / 本项目实测 / 差距清单            │
│               「我该改什么，按什么顺序改」                 │
├──────────────────────────────────────────────────────────┤
│ 04  选型层    四种方法的取舍 / 决策树 / 为什么不是越新越好 │
│               「我这个场景该用哪种」                       │
├──────────────────────────────────────────────────────────┤
│ 03  原理层    约束解码为什么能 100% 保证 / 文法不等于 JSON │
│               「凭什么它比提示词可靠」  ← 分水岭           │
├──────────────────────────────────────────────────────────┤
│ 02  方法层    提示词 / JSON Mode / 假函数 / 约束解码       │
│               「一共有几种做法，各长什么样」               │
├──────────────────────────────────────────────────────────┤
│ 01  概念层    结构化输出在解决什么 / 三层可靠性            │
│               「失败了，到底是哪一层的锅」                 │
├──────────────────────────────────────────────────────────┤
│ 00  前置层    token / 采样 / API 结构 / JSON Schema        │
│               「读懂上面四层所需的全部基础」               │
└──────────────────────────────────────────────────────────┘
```

**03 是分水岭。** 在它之前，「结构化输出」看起来只是「换个参数写法」；理解约束解码之后才会明白，**这四种方法之间是「请求」与「物理不可能」的区别**，不是风格差异。

## 2. 阅读顺序

| # | 章节 | 前置 | 预计 | 学完你能做什么 |
|---|---|---|---|---|
| 00 | [前置知识](00-prerequisites.md) | 会 Python | 30 min | 看懂一次 API 调用的每个字段；解释「为什么 content 空了却烧了 800 token」 |

| 02 | [四种实现方法](02-methods.md) | 01 | 25 min | 认得出四种写法；解释「假函数为什么不执行任何函数」 |

| 04 | [选型与取舍](04-choosing.md) | 03 | 20 min | 给一个端点选出方案；说清约束解码的代价 |
| 05 | [本项目现状](05-this-project.md) | 04 | 20 min | 读懂本项目的实测结论；知道该先改什么 |

**总计约 2 小时。** 每章末尾都有「深入阅读」，指向深文对应小节。

## 3. 三条路径
