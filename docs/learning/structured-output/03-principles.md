# 03 · 约束解码原理

> **前置**：[02 · 四种实现方法](02-methods.md)，以及 [00 § 1](00-prerequisites.md#1-模型是怎么生成一个-token-的)（token / logits / 采样的分工）
> **本章目标**：搞懂「数学保证」和「概率很高」的区别。这是本专题的分水岭。
> **预计**：20 min

---

## 1. 机制：在采样之前动手

两个已知的前提：

- §00 §1.3 —— **模型算出 logits（一张全词表打分表），采样器拿着表挑一个。**
- §00 §2.4 推论 C —— **任何格式约束都必须在「采样之前」介入**，因为 token 一旦采出来就不能反悔，不存在「生成完再修正」这条路。

那么位置就唯一了：约束解码插在这两者之间。

```
                        ┌─────────────────────────────┐
   已生成前缀           │  模型前向传播               │
   {"confidence":  ───▶ │  → 全词表 logits            │
                        └──────────────┬──────────────┘
                                       │
                        ┌──────────────▼──────────────┐
                        │  语法状态机                  │  ← 约束解码在这里
                        │  「当前位置只能接数字」       │
                        │  → 把所有非数字 token        │
                        │     的概率强行置为 -inf      │
                        └──────────────┬──────────────┘
                                       │
                                  采样 ▼
                                只可能是 0-9
```

关键在最后一句：

> **模型不是「被要求」输出合法 JSON，而是它在物理上没有能力输出非法 JSON**——那些 token 根本不在候选集里，概率是 0。

这就是**数学保证**和**概率很高**的区别。提示词能被忽略，训练偏好会失效，但**一个概率为 0 的 token 不可能被采样出来**。

---

## 2. 三条推论

理解了机制，很多困惑自动解开。

### 推论 A：它保证不了 ③ 语义层

约束能让模型必须输出 `keep`/`drop`/`borderline` 之一，**但不能让它输出正确的那个**。

§01 §3 那张三层表里的第 ③ 行，约束解码一个字都没碰。

### 推论 B：截断仍然会炸

约束解码保证「**生成出来的部分**合法」，不保证「写得完」。

撞上 `max_tokens` 照样被切断，切断的 JSON 照样非法。**这一层永远要自己管**（§00 §4）。

### 推论 C：它住在服务层，不在模型里

约束解码是**采样器**的功能，而采样器属于推理服务器（§00 §7.1）。

所以：

> **同一份模型权重，换个服务栈，可能有、也可能没有 `json_schema`。**

推论的推论：「新模型是不是不需要假函数了」这个问法**问错了对象**。该问的是「**我的端点支不支持**」。模型新不新几乎不相关。

## 3. 「语法」不等于 JSON

前两节一直拿 JSON 举例，但**这个机制跟 JSON 没有任何绑定关系**。这里的「语法」是形式语言意义上的 grammar。

### 3.1 它真正需要的能力

只有一个：**给定已生成的前缀，能回答「下一个 token 有哪些合法」**。

任何能回答这个问题的形式化描述都能用：

| 约束形式 | 例子 | 典型实现【文献】 |
|---|---|---|
| **枚举 / 选择** | 只能是 `keep`/`drop`/`borderline` | 最简单，屏蔽所有偏离候选串的 token |
| **正则** | `^\d{4}-\d{2}-\d{2}$`（日期） | Outlines、vLLM `guided_regex` |
| **JSON Schema** | 你熟悉的那个 | 先编译成 CFG，是上一层的特例 |
| **任意上下文无关文法（CFG）** | SQL、XML、Cypher、自定义 DSL | llama.cpp **GBNF**、XGrammar、guidance |

所以你完全可以约束模型：

- **只能输出合法 SQL**——给它 SQLite 文法 + 你的表名列名，它连「查询不存在的列」都做不到
- **只能输出闭合的 XML**
- **只能输出 `0`/`1`/`2`/`3` 四个字符之一**——这时你连解析都不需要了

> **JSON Schema 只是「把常用的一类 CFG 包了个标准化的壳」。** 厂商 API 为通用性只暴露这一层；本地推理（llama.cpp / vLLM / Outlines）能给你完整 CFG 表达力。

### 3.2 那为什么现实中几乎全是 JSON

1. **JSON Schema 是既成标准**，pydantic / TypeScript / OpenAPI 一键互转（§00 §5）。生态优势压倒一切。
2. **文法极小、好编译**——嵌套靠一个栈就能跟踪。
3. **训练数据里密度极高**，模型对它的先验最强。这条比想象中重要：约束解码保证形式，但**把模型逼进陌生格式会让内容质量崩**。
4. **厂商要选通用最大公约数**。

### 3.3 两个限制

**限制一：不是所有格式都能被完整约束。**

需要能在**任意前缀处**判断合法集。正则语言和大部分 CFG 没问题，但**上下文相关**的东西无能为力：

- **Python 缩进**（层级依赖上下文，不是 CFG）
- **YAML**（缩进敏感 + 大量隐式类型规则，臭名昭著地难约束）
- **「变量须先声明后使用」**——这压根不是语法问题，是语义问题

所以：保证「合法 JSON」的库很多，保证「合法 Python」的基本没有。

**限制二：字符 vs token 的错位。**

**文法定义在字符上，模型生成的是 token**（§00 §1.1），而一个 token 可能横跨语法边界。

比如词表里有个 token 就是 `":`（引号+冒号连在一起）。当状态机说「现在必须先来一个 `"` 结束字符串」时，这个 token 合不合法？合法的话它顺带把冒号也吐出来了，状态机得跟着跳两步。

处理这个叫 **token healing / token-grammar alignment**，是 XGrammar 这类库的核心工作量。用现成库时不用管，但它解释了为什么「约束解码」听起来简单、实现却自成一个技术领域。

## 4. 一个实用衍生：无约束时该选什么格式

§3.2 说了 JSON 在**有约束**时是最优解。但反过来——**在无约束的场景下（也就是 §02 §1 那条路），JSON 恰恰是最脆弱的格式之一。**

因为它要求字符串内部转义：

```json
{"decision": "keep", "reason": "文档里说 "北极星" 是..."}   ← 炸了，引号未转义
{"decision": "keep", "reason": "第一点...
第二点..."}                                                ← 炸了，裸换行非法
```

而 `reason` 是模型自由生成的长文本，出现引号、换行是常态。**模型必须一边思考内容、一边正确转义——这是两个任务，它经常只顾得上一个。**

标签式格式没有这个问题：

```xml
<reason>文档里说 "北极星" 是...
可以随便换行、随便打引号，没有任何字符需要转义</reason>
<decision>keep</decision>
<confidence>0.85</confidence>
```

用 `<decision>(.*?)</decision>` 挖，**不存在「解析全炸」**——某字段挖不出时其他字段照拿，可做**字段级降级**。

> 顺带解释一个现象：Anthropic 早期一直建议用 XML 标签而非 JSON 组织输入输出。不是品味问题，是**无约束生成下标签格式的鲁棒性确实更好**。

## 5. 本章小结

| 问题 | 答案 |
|---|---|
| 为什么是「数学保证」 | 违规 token 概率被置为 0，**物理上采样不出来** |
| 它保证不了什么 | ③ 语义层；以及**截断** |
| 为什么说它「住在服务层」 | 它是采样器的功能，跟模型权重无关 |
| 「语法」一定是 JSON 吗 | **不是**。枚举 / 正则 / 任意 CFG 都行 |
| 什么约束不了 | 上下文相关的东西（Python 缩进、YAML） |
| 无约束时该用什么格式 | **XML 标签 > JSON**，因为不需要转义 |
