## 什么是装饰器

装饰器(Decorator)是Python中一种强大的语法特性，它本质上是一个**函数(或类)，可以修改或增强其他函数或类的行为**，而不需要直接修改原有代码。装饰器使用 `@decorator_name` 语法放在函数或类定义之前。

### 核心概念

```python
@decorator
def function():
    pass

# 等价于:
function = decorator(function)
```

装饰器允许我们在不修改原函数代码的情况下，为其添加额外功能。

## 项目中使用的装饰器

根据代码分析，本项目主要使用了以下几类装饰器：

### 1. @dataclass (最常用)

**位置:** `src/core/settings.py`

这是Python标准库的装饰器，用于自动生成类的特殊方法(__init__、__repr__等)。

```python
@dataclass
class LLMSettings:
    provider: str
    model: str
    api_key: Optional[str] = None
    temperature: float = 0.7
```

**作用:**
- 自动生成 `__init__()` 方法，避免手写构造函数
- 自动生成 `__repr__()` 用于打印对象
- 自动生成 `__eq__()` 用于对象比较
- 大幅减少样板代码

在本项目中，所有配置类都用了 `@dataclass` (LLMSettings, EmbeddingSettings, SplitterSettings等12个配置类)。

### 2. @abstractmethod (接口定义)

**位置:** `src/libs/*/base_*.py` (所有基类)

来自 `abc` 模块，用于定义抽象方法，强制子类实现。

```python
from abc import ABC, abstractmethod

class BaseLLM(ABC):
    @abstractmethod
    def generate(self, prompt: str, **kwargs) -> str:
        """子类必须实现这个方法"""
        pass
```

**作用:**
- 定义接口规范，强制所有LLM提供者(Azure/OpenAI/Ollama)必须实现 `generate()` 方法
- 如果子类没实现抽象方法，实例化时会报错
- 保证了项目的"可插拔架构"能正常工作

**项目中的使用位置:**
- `BaseLLM.chat()` (src/libs/llm/base_llm.py:27)
- `BaseEmbedding.encode()` (src/libs/embedding/base_embedding.py:27)
- `BaseSplitter.split()` (src/libs/splitter/base_splitter.py:27)
- `BaseReranker.rerank()` (src/libs/reranker/base_reranker.py:27)
- `BaseEvaluator.evaluate()` (src/libs/evaluator/base_evaluator.py:30)
- `BaseVectorStore.upsert/query()` (src/libs/vector_store/base_vector_store.py:27,61)

### 3. @classmethod (工厂模式)

**位置:** 所有 `*_factory.py` 文件

用于定义类方法，第一个参数是类本身(cls)，而不是实例(self)。

```python
class LLMFactory:
    _providers = {}

    @classmethod
    def register_provider(cls, name: str, provider_class: Type[BaseLLM]):
        """注册LLM提供者"""
        cls._providers[name] = provider_class

    @classmethod
    def create(cls, settings: LLMSettings) -> BaseLLM:
        """根据配置创建LLM实例"""
        provider_class = cls._providers.get(settings.provider)
        return provider_class(settings)
```

**作用:**
- 不需要创建工厂实例就能调用方法：`LLMFactory.create(settings)`
- 管理类级别的共享状态(如 `_providers` 注册表)
- 实现工厂模式的核心机制

## 类变量与类方法深入讲解

在深入理解 `@classmethod` 实现工厂模式之前，需要先理解Python中的类变量和类方法概念。

### 类变量 vs 实例变量

#### 类变量(Class Variable)

**定义方式:** 直接在类体中定义，而不是在 `__init__` 方法中

```python
class MyClass:
    # 类变量 - 所有实例共享
    class_var = "我是类变量"

    def __init__(self):
        # 实例变量 - 每个实例独立
        self.instance_var = "我是实例变量"
```

**特点:**
- **所有实例共享同一份数据**
- 通过类名或实例都可以访问
- 修改类变量会影响所有实例

**示例:**
```python
class Counter:
    count = 0  # 类变量，统计创建了多少实例

    def __init__(self):
        Counter.count += 1  # 通过类名访问
        self.id = Counter.count  # 每个实例的ID

# 创建实例
obj1 = Counter()
obj2 = Counter()
obj3 = Counter()

print(Counter.count)  # 3 - 类变量
print(obj1.id)        # 1 - 实例变量
print(obj2.id)        # 2 - 实例变量
```

#### 项目中的类变量

```python
class LLMFactory:
    # 这是类变量！所有地方访问的都是同一个字典
    _PROVIDERS: dict[str, type[BaseLLM]] = {}

    @classmethod
    def register_provider(cls, name: str, provider_class):
        # 修改类变量，全局生效
        cls._PROVIDERS[name] = provider_class
```

**为什么要用类变量？**
- 所有注册的提供者需要全局可见
- 不希望每次创建工厂实例时都丢失注册信息

### 类方法 vs 实例方法 vs 静态方法

#### 1. 实例方法(Instance Method)

**定义:** 第一个参数是 `self`，表示实例本身

```python
class Dog:
    def __init__(self, name):
        self.name = name  # 实例变量

    def bark(self):  # 实例方法
        print(f"{self.name} says woof!")

dog = Dog("Buddy")
dog.bark()  # 通过实例调用
```

#### 2. 类方法(Class Method)

**定义:** 用 `@classmethod` 装饰，第一个参数是 `cls`，表示类本身

```python
class Dog:
    species = "Canis familiaris"  # 类变量

    @classmethod
    def get_species(cls):  # 类方法
        return cls.species

    @classmethod
    def create_puppy(cls, name):  # 工厂方法
        return cls(name)  # cls就是Dog类

# 调用类方法 - 不需要创建实例
print(Dog.get_species())  # "Canis familiaris"
puppy = Dog.create_puppy("Max")  # 通过类方法创建实例
```

#### 3. 静态方法(Static Method)

**定义:** 用 `@staticmethod` 装饰，没有特殊的第一个参数

```python
class MathUtils:
    @staticmethod
    def add(x, y):  # 静态方法 - 不需要self或cls
        return x + y

# 调用静态方法
result = MathUtils.add(5, 3)  # 8
```

### 三者对比

| 类型 | 装饰器 | 第一个参数 | 可以访问 | 调用方式 |
|-----|--------|-----------|---------|---------|
| 实例方法 | 无 | `self` | 实例变量、类变量 | `obj.method()` |
| 类方法 | `@classmethod` | `cls` | 类变量(不能访问实例变量) | `Class.method()` 或 `obj.method()` |
| 静态方法 | `@staticmethod` | 无 | 都不能直接访问 | `Class.method()` 或 `obj.method()` |

### 完整示例：工厂模式中的类变量和类方法

```python
class LLMFactory:
    # 1. 类变量定义 - 直接在类体中，不在__init__里
    _PROVIDERS = {}  # 所有实例共享这个字典

    # 2. 类方法定义 - 用@classmethod装饰
    @classmethod
    def register_provider(cls, name, provider_class):
        """
        cls 参数指向 LLMFactory 类本身
        cls._PROVIDERS 访问类变量
        """
        cls._PROVIDERS[name] = provider_class

    @classmethod
    def create(cls, settings):
        """
        通过类方法创建实例，不需要先创建工厂对象
        """
        provider_class = cls._PROVIDERS.get(settings.provider)
        return provider_class(settings)

    # 3. 实例方法（如果需要的话）
    def __init__(self):
        """
        工厂模式通常不需要实例化，所以没有这个方法
        """
        pass

# 使用 - 注意：没有创建LLMFactory的实例！
LLMFactory.register_provider("openai", OpenAILLM)  # 直接用类名调用
llm = LLMFactory.create(settings)  # 直接用类名调用
```

### 为什么不用实例方法？

```python
# 如果用实例方法（错误示范）
class BadFactory:
    def __init__(self):
        self._providers = {}  # 实例变量

    def register(self, name, provider):
        self._providers[name] = provider

# 问题：每次创建新实例，注册信息就丢失了

factory2.create(settings)  # 失败！factory2的_providers是空的
```

## @classmethod实现工厂模式详解

这是本项目最核心的设计模式之一，是一个**教科书级别的工厂模式实现**。

### 核心机制：注册表模式的工厂

#### 第一步：定义类级别的注册表

```python
class LLMFactory:
    # 关键：这是一个类变量，不是实例变量
    # 所有LLMFactory的方法都共享这个字典
    _PROVIDERS: dict[str, type[BaseLLM]] = {}
```

**为什么用类变量？**
- 所有提供者(OpenAI、Azure、Ollama等)注册后，**全局可见**
- 不需要创建工厂实例：`LLMFactory.create()` 而不是 `LLMFactory().create()`

#### 第二步：用@classmethod提供注册方法

```python
@classmethod
def register_provider(cls, name: str, provider_class: type[BaseLLM]) -> None:
    """注册新的LLM提供者"""
    if not issubclass(provider_class, BaseLLM):
        raise ValueError(f"必须继承自BaseLLM")

    # cls指向LLMFactory类本身
    # 修改类级别的_PROVIDERS注册表
    cls._PROVIDERS[name.lower()] = provider_class
```

**@classmethod的作用:**
- 第一个参数 `cls` 是**类本身**(LLMFactory)，不是实例
- 可以访问和修改类变量 `cls._PROVIDERS`
- 调用方式：`LLMFactory.register_provider("openai", OpenAILLM)`

#### 第三步：用@classmethod提供创建方法

```python
@classmethod
def create(cls, settings: Settings, **override_kwargs: Any) -> BaseLLM:
    """根据配置创建LLM实例"""

    # 1. 从settings.yaml读取提供者名称
    provider_name = settings.llm.provider.lower()  # 例如: "openai"

    # 2. 从注册表查找对应的类
    provider_class = cls._PROVIDERS.get(provider_name)  # 获取OpenAILLM类

    # 3. 实例化并返回
    return provider_class(settings=settings, **override_kwargs)
```

**工作流程:**
```
settings.yaml: llm.provider = "openai"
       ↓
LLMFactory.create(settings)
       ↓
查找 _PROVIDERS["openai"] → OpenAILLM类
       ↓
实例化: OpenAILLM(settings=settings)
       ↓
返回: BaseLLM实例
```

#### 第四步：模块导入时自动注册

这是最巧妙的部分！

```python
# llm_factory.py 文件底部

def _register_builtin_providers() -> None:
    """注册内置LLM提供者"""
    try:
        from src.libs.llm.openai_llm import OpenAILLM
        LLMFactory.register_provider("openai", OpenAILLM)
    except ImportError:
        pass  # OpenAI库未安装，跳过

    try:
        from src.libs.llm.azure_llm import AzureLLM
        LLMFactory.register_provider("azure", AzureLLM)
    except ImportError:
        pass

    # ...ollama, deepseek等

# 模块导入时立即执行注册
_register_builtin_providers()
```

**自动注册的优势:**
- 当你 `import LLMFactory` 时，所有提供者自动注册完毕
- 新增提供者只需：
  1. 创建新的类文件(如 `anthropic_llm.py`)
  2. 在 `_register_builtin_providers()` 加一段注册代码
  3. **无需修改其他任何代码！**

### 为什么@classmethod是关键？

#### 对比：如果不用@classmethod会怎样？

**错误方案1：用实例方法**
```python
class BadFactory:
    def __init__(self):
        self._providers = {}  # 实例变量

    def register(self, name, cls):
        self._providers[name] = cls

# 问题：每次都要创建实例
factory1 = BadFactory()
factory1.register("openai", OpenAILLM)

factory2 = BadFactory()  # 新实例，注册表是空的！
factory2.create(settings)  # 失败！找不到"openai"
```

**错误方案2：用静态方法+全局变量**
```python
_GLOBAL_PROVIDERS = {}  # 全局变量，不优雅

class UglyFactory:
    @staticmethod
    def register(name, cls):
        _GLOBAL_PROVIDERS[name] = cls  # 依赖全局变量
```

**正确方案：@classmethod**
```python
class LLMFactory:
    _PROVIDERS = {}  # 类变量，优雅地封装在类内

    @classmethod
    def register(cls, name, provider):
        cls._PROVIDERS[name] = provider  # 通过cls访问类变量
```

**优势:**
- 注册表封装在类内(不污染全局命名空间)
- 无需创建实例就能调用：`LLMFactory.register()`
- 类方法可以访问类级别状态(`cls._PROVIDERS`)

## 类方法vs静态方法详解

理解类方法和静态方法的区别对于选择正确的设计至关重要。

### 核心区别对比

```python
class MyClass:
    class_var = "我是类变量"

    @classmethod
    def class_method(cls, x):
        # cls 是类本身，可以访问类变量和类方法
        return f"{cls.class_var} - {x}"

    @staticmethod
    def static_method(x):
        # 没有 cls 或 self，不能直接访问类/实例的任何内容
        return f"Static - {x}"
```

| 特性 | 类方法 `@classmethod` | 静态方法 `@staticmethod` |
|-----|---------------------|----------------------|
| **第一个参数** | `cls`（类本身） | 无特殊参数 |
| **访问类变量** | ✅ 可以通过 `cls.变量名` | ❌ 不能直接访问 |
| **访问类方法** | ✅ 可以通过 `cls.方法名()` | ❌ 不能直接访问 |
| **继承行为** | `cls` 指向调用的子类 | 无继承感知 |
| **典型用途** | 工厂方法、操作类状态 | 工具函数、无状态逻辑 |

### 详细示例

#### 1. 类方法：能访问类变量和类方法

```python
class Pizza:
    # 类变量
    default_size = "medium"
    _order_count = 0

    def __init__(self, toppings):
        self.toppings = toppings

    @classmethod
    def margherita(cls):
        """工厂方法：创建玛格丽特披萨"""
        # cls 可以访问类变量
        print(f"Default size: {cls.default_size}")

        # cls 可以调用构造函数
        return cls(["tomato", "mozzarella", "basil"])

    @classmethod
    def increment_orders(cls):
        """操作类变量"""
        cls._order_count += 1
        return cls._order_count

# 使用类方法
pizza = Pizza.margherita()  # 创建实例
count = Pizza.increment_orders()  # 修改类变量
```

#### 2. 静态方法：纯工具函数

```python
class Pizza:
    @staticmethod
    def validate_toppings(toppings):
        """验证配料是否合法（与类状态无关）"""
        forbidden = ["pineapple"]  # 只是个示例

        for topping in toppings:
            if topping in forbidden:
                return False
        return True

    @staticmethod
    def calculate_price(size, topping_count):
        """计算价格（纯数学计算，不依赖类状态）"""
        base_prices = {"small": 8, "medium": 10, "large": 12}
        return base_prices[size] + topping_count * 1.5

# 使用静态方法
is_valid = Pizza.validate_toppings(["mushroom", "pepper"])
price = Pizza.calculate_price("large", 3)
```

### 继承时的重要区别

这是最关键的区别！

```python
class Animal:
    species = "Generic Animal"

    @classmethod
    def get_species(cls):
        # cls 会指向调用的类（子类或父类）
        return cls.species

    @staticmethod
    def make_sound():
        # 静态方法不知道是谁调用的
        return "Some sound"

class Dog(Animal):
    species = "Canis familiaris"

class Cat(Animal):
    species = "Felis catus"

# 类方法会感知继承
print(Dog.get_species())  # "Canis familiaris" ✅ cls 是 Dog
print(Cat.get_species())  # "Felis catus" ✅ cls 是 Cat

# 静态方法不感知继承
print(Dog.make_sound())  # "Some sound" (总是一样)
print(Cat.make_sound())  # "Some sound" (总是一样)
```

### 项目中的实际应用

#### 类方法：LLMFactory（正确选择）

```python
class LLMFactory:
    _PROVIDERS = {}  # 类变量

    @classmethod
    def register_provider(cls, name, provider_class):
        # ✅ 需要访问类变量 _PROVIDERS
        cls._PROVIDERS[name] = provider_class

```

**为什么用类方法？**
- 需要访问和修改类变量 `_PROVIDERS`
- 如果有子类扩展，`cls` 会指向正确的子类

#### 如果改成静态方法会怎样？❌

```python
class LLMFactory:
    _PROVIDERS = {}

    @staticmethod
    def register_provider(name, provider_class):
        # ❌ 不能用 cls，必须硬编码类名
        LLMFactory._PROVIDERS[name] = provider_class
        # 问题：如果有子类继承，还是操作父类的 _PROVIDERS

    @staticmethod

```

**问题:**
- 必须硬编码 `LLMFactory`，失去灵活性
- 继承扩展时会出问题

### 如何选择？决策树

```
需要访问或修改类变量/类方法？
  │
  ├─ 是 → 使用 @classmethod
  │      示例：工厂方法、操作类状态、备用构造器
  │
  └─ 否 → 需要访问实例变量？
         │
         ├─ 是 → 使用普通方法（self）
         │
         └─ 否 → 使用 @staticmethod
                示例：工具函数、验证逻辑、数学计算
```

### 典型使用场景

#### @classmethod 适用场景

**1. 工厂方法**
```python
class Date:
    def __init__(self, year, month, day):
        self.year = year
        self.month = month
        self.day = day

    @classmethod
    def from_string(cls, date_str):
        """从字符串创建日期"""
        year, month, day = map(int, date_str.split('-'))
        return cls(year, month, day)  # cls 可以创建实例

    @classmethod
    def today(cls):
        """创建今天的日期"""
        import datetime
        today = datetime.date.today()
        return cls(today.year, today.month, today.day)

# 使用
date1 = Date.from_string("2024-01-15")
date2 = Date.today()
```

```python
class Database:

    def get_connection(cls):
        return cls.connection_pool.pop() if cls.connection_pool else None
```

```python
class StringUtils:

    def is_palindrome(text):
        """检查是否是回文"""
        return text == text[::-1]

    @staticmethod
    def capitalize_words(text):
        """每个单词首字母大写"""
        return ' '.join(word.capitalize() for word in text.split())

# 使用
result = StringUtils.is_palindrome("radar")
```

```python
class User:
    @staticmethod
    def is_valid_email(email):
        """验证邮箱格式（不需要访问类/实例）"""
        import re
        pattern = r'^[\w\.-]+@[\w\.-]+\.\w+$'
        return bool(re.match(pattern, email))

# 使用
```

### 常见误区

#### 误区1：过度使用静态方法

```python
# ❌ 不好：静态方法放在类里只是为了"组织代码"
class MathUtils:
    @staticmethod
    def add(a, b):
        return a + b

    @staticmethod
    def multiply(a, b):
        return a * b

# ✅ 更好：如果完全不需要类特性，用模块函数
# math_utils.py
def add(a, b):
    return a + b

def multiply(a, b):
    return a * b
```

#### 误区2：该用类方法却用静态方法

```python
# ❌ 错误：需要访问类变量却用静态方法
class Counter:
    count = 0

    @staticmethod
    def increment():
        Counter.count += 1  # 硬编码类名，继承时有问题

# ✅ 正确：用类方法
class Counter:
    count = 0

    @classmethod
    def increment(cls):
        cls.count += 1  # 通过 cls 访问，支持继承
```

### 快速记忆口诀

- **类方法**：需要"类"的信息，加 `@classmethod`
- **静态方法**：完全独立，纯工具，加 `@staticmethod`
- **实例方法**：需要"实例"数据，用 `self`

### 选择总结

**选择 @classmethod 当你需要：**
1. 访问或修改类变量
2. 创建实例的备用构造器（工厂方法）
3. 实现注册表模式
4. 操作类级别的状态

**选择 @staticmethod 当你有：**
1. 与类逻辑相关但不需要访问类/实例状态的工具函数
2. 纯函数式的计算逻辑
3. 验证/格式化等独立功能

**本项目的选择正确性：**
- `LLMFactory.register_provider()` 用 `@classmethod` ✅
  - 原因：需要修改 `cls._PROVIDERS` 类变量
- 如果项目里有纯工具函数（如字符串处理），应该用 `@staticmethod`

## 设计模式优势

### 装饰器在项目中的优势

1. **代码简洁性**: `@dataclass` 消除了大量样板代码
2. **架构保证**: `@abstractmethod` 强制所有提供者实现相同接口
3. **灵活性**: `@classmethod` 让工厂模式易于扩展新提供者
4. **可测试性**: `@pytest.fixture` 和 `@pytest.mark.unit` 让测试结构清晰

这些装饰器共同支撑了项目的**可插拔架构设计**——通过修改 `settings.yaml` 切换任何组件，无需改代码。

### 工厂模式的优雅之处

#### 1. 开闭原则(Open-Closed)

- 新增Anthropic提供者，只需添加 `anthropic_llm.py` 和一行注册代码
- 无需修改LLMFactory或其他提供者的代码

#### 2. 配置驱动(Config-Driven)

- 切换提供者只需修改YAML，不动Python代码
- 支持环境变量注入(`${OPENAI_API_KEY}`)

#### 3. 类型安全(Fail-Fast)

- `register_provider` 验证类必须继承 `BaseLLM`
- `create` 方法会验证提供者是否存在，给出清晰错误

#### 4. 自动发现(Auto-Discovery)

- 模块导入时自动注册所有提供者
- `_register_builtin_providers()` 机制

#### 5. 无状态工厂(Stateless)

- `@classmethod` 确保工厂本身不需要实例化
- 注册表是类级别的，全局唯一

## 总结

本项目通过 `@classmethod` 实现的工厂模式是**教科书级别的设计模式实践**，完美支撑了"可插拔架构"的核心理念。

**关键要点：**

1. **@dataclass** 简化配置类定义
2. **@abstractmethod** 定义统一接口，保证可插拔性
3. **@classmethod** 实现无状态工厂，支持动态提供者注册
4. **类变量** 提供全局共享的注册表
5. **自动注册机制** 让新增提供者变得简单
6. **配置驱动** 实现零代码切换组件

**类方法vs静态方法选择原则：**

- 需要访问类变量 → `@classmethod`
- 纯工具函数，无状态 → `@staticmethod`
- 需要访问实例数据 → 普通方法(self)

这种设计让系统具有极高的**可扩展性**和**可维护性**，是构建大型模块化系统的优秀实践。
