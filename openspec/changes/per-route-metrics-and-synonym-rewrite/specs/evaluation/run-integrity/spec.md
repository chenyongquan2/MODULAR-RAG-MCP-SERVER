## ADDED Requirements

### Requirement: 检索类指标必须按检索路径分别披露

评估报告 SHALL 在融合后的检索类指标之外，为**每一条参与检索的路径**分别给出该路自身的检索类指标。路径的划分与实际执行的检索路径一致，至少包含稠密路径与稀疏路径。

理由：融合后的指标量的是最终结果，而单路的改善会被该路在融合中的权重稀释。本项目稀疏路径的生效权重仅为稠密路径的十分之一，因此任何只作用于稀疏路径的改进，其效果在融合后指标上几乎不可见 —— 会得出「没有效果」的错误结论，而改善实际发生了，只是被融合口径掩盖。这与本能力既有的「披露有效分母」是同一类要求的另一个维度：**前者防止分母被静默收缩，后者防止改善被静默稀释。**

#### Scenario: 分路径指标与融合后指标并存

- **WHEN** 一次评估同时执行了稠密与稀疏两路检索
- **THEN** 报告中既有融合后的检索类指标，也有稠密路与稀疏路各自的同名指标
- **AND** 两者可被区分，不会因命名相同而混淆

#### Scenario: 某一路无结果

- **WHEN** 某条用例上稀疏路返回空结果
- **THEN** 该路在这条用例上的检索类指标按「未命中」计入，而非跳过该用例
- **AND** 该路的聚合分母仍为全部用例数

#### Scenario: 单路指标可被独立核对

- **WHEN** 融合权重被配置为只保留其中一路（其余路权重为零）
- **THEN** 该路的分路径指标与此时的融合后指标相等

  这是它们在定义上应当相等的情形，因此可作为分路径指标实现是否正确的自检手段。

#### Scenario: 不增加检索次数

- **WHEN** 报告需要产出分路径指标
- **THEN** 不额外执行任何一次检索 —— 各路结果在融合前本就已经取得，分路径指标只是对已有结果各自评分一次

#### Scenario: 关闭融合时仍然可用

- **WHEN** 评估在只启用纯计算类指标（不调用判定模型）的模式下运行
- **THEN** 分路径指标照常产出

  这是纯检索改动做 A/B 时的常用模式，若分路径指标依赖判定模型才可用，就恰好在最需要它的场景下缺席。
